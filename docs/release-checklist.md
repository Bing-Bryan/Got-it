# 发布可靠性测试计划

适用：v0.1.0 本机早期试用版。先支持已验收的 macOS；不承诺生产级公网部署。测试目标是发现安装、数据丢失、状态失真与公开材料风险，不能证明零 bug。

## 自动化门槛（每次提交）

| 检查 | 命令 / 方法 | 通过条件 |
| --- | --- | --- |
| 干净安装 | 在公开快照执行 `npm ci` | 不借用工作目录 node_modules，锁文件不改动 |
| 类型与构建 | `npm run build` | 无编译错误，生成可访问资源 |
| 逻辑与集成回归 | `npm test` | 全部通过；保存/冲突/迁移/来源读取/流式中断覆盖沿用现有套件 |
| 成品启动 | `npm run test:release` | HTML、JS/CSS 可访问；非法 API、会话与外站请求正确拒绝；缺少 Codex 不伪装连接；重启旧会话失效 |
| 依赖 | `npm audit --audit-level=high` | 无未处理的 high/critical；其他级别逐项评估 |
| 分发材料 | `npm run release:prepare` | 白名单复制与文本扫描成功，无原 Git 历史和用户数据；截图人工复核 |

GitHub Actions 对三个系统执行这些检查。远程执行结果出来前，Windows/Linux 仍标实验性；API/单元测试通过也不等于系统选择器等原生交互已验收。

## 真人 / 真实浏览器门槛（发布候选版本）

1. 使用隔离的 `GOT_IT_DATA_DIR` 和独立浏览器入口；记录系统、Node、浏览器、Codex 版本。
2. 导入真实 Markdown，确认目录、正文和保存成功；不得修改源文件。
3. 从原文选区分别生成概念解释、来源查找、产品介绍，记录实际结果与模型，不以模拟内容替代。
4. 查看来源链接与核对状态；不能把有链接当成核查成功。确认理解后保持独立证据结论。
5. 实际停止一轮请求，确认未完成/中断且旧答案保留；切换/刷新不应自动请求。
6. 关闭服务和页面，再打开同一数据目录，确认原文、三个知识贴、回答和学习状态恢复。
7. 检查保存失败/冲突、损坏记录、旧格式迁移、恶意 Markdown、来源网络边界的自动测试结果；需要声称真实磁盘满/断电时另做专项，不能用模拟通过替代。
8. 桌面截图及 390px 窄屏检查；不要求本轮全面视觉改版。
9. 首次未登录账号：真人完成官方登录、取消和失败重试。不得为测试读取凭据、自动操作授权或注销用户现有账号。未完成时明确标记待人工验收。
10. 审核 README 截图无账户信息、原始路径或私密片段；完整报告不分发。

## 发布判断

阻断：干净安装/构建/启动失败、已知数据丢失、凭据泄露、伪造完成、无法理解的关键错误。早期试用版允许明确披露的首次真人授权和非主平台覆盖缺口；正式稳定版须先补齐。

完成自动化与已授权真人流程后记录在 `release-results.md`。准备快照不等于发布：本任务不创建远程仓库、不推送。

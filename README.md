# got it

**简体中文** · [English](README.en.md)

**读到不懂的地方，就在原文旁弄明白。**

got it 是本地优先的 Markdown、PDF 和网页文章阅读器。把材料加入阅读库，选中原文后解释概念、查找来源或提出具体问题，回答会作为知识贴留在原文旁，方便继续阅读、刷新后恢复和日后回看。

AI 通常只在你明确选择功能或发送问题后工作；如果事先开启「以后自动翻译」，之后确认加入的新英文网页会按该偏好开始翻译。原文件保持不变；阅读副本、知识贴、译文和进度保存在本机。

> **v0.1.0 · 早期试用版。** 适合已有 Codex 使用经验的读者。当前已验证 macOS Apple Silicon；Windows/Linux 尚未实机验收。没有账号、云同步或多人协作。

## 一次完整的阅读旅程

本轮 Markdown、PDF 与含图片网页展示截图于 **2026-10-14** 使用隔离阅读库拍摄，呈现当前小写品牌和紫色 g 标识。Markdown 与 PDF 使用自制合成材料；网页来自 [Simon Willison 的公开文章](https://simonwillison.net/2026/Oct/9/built-using-my-voice/)，实际导入并保存静态图片。拍摄未发起模型请求。知识贴回答和框选截图保留 2026-10-12 的界面与已保存真实回答，不代表当前品牌样式；示例中的数字和回答仍需读者自行判断。

### 1. 把材料放进同一个阅读库

Markdown、PDF 和已导入网页可以共存。左上角独立「+」按钮添加材料，悬停可展开菜单；本地文件标明「MD / PDF」，网页链接标明「静态文章 / X」。菜单支持点击、键盘和触摸，离开按钮与菜单的联合区域后收起。旁边的资料库按文件名或网页标题搜索，切换已有材料不会自动生成回答。网页条目保留原始链接，本地文件显示来源路径或关联状态。

> 当前品牌统一使用小写 `got it`（连字符写法 `got-it`）。本次品牌与阅读展示见[更新说明](docs/updates/2026-10-14-brand-and-reading-showcase.md)，公开仓库为 [Bing-Bryan/got-it](https://github.com/Bing-Bryan/got-it)。既有 `Got-it` 数据目录保留原拼写。

![当前 got it 阅读界面：Markdown 原文、目录和知识贴面板](docs/images/reading-2026-10-14.png)

### 2. 留在原文里阅读

左侧目录定位章节，中间阅读原文，右侧回看与选区相连的知识贴。Markdown 保留标题、列表和表格；PDF 保留原始图文版面；网页保存可阅读的正文、链接、代码和必要静态图片。

![Markdown 阅读界面：原文、目录和知识贴并排显示](docs/images/reading-2026-10-14.png)

左右侧栏可独立固定或收起，知识贴面板可调宽。Markdown 可调正文宽度；PDF 可缩放或恢复自动适合宽度。窄屏时侧栏改为抽屉。

### 3. 选中原文，选择理解方式

- **解释一下：** 说明术语、人物、公司、产品或难懂段落；需要外部背景时按需查阅资料。
- **查找来源：** 对数字或主张发起一次有时限的查找，区分搜索是否执行、片段是否核对，以及证据是否真正支持原句。
- **问一问：** 围绕选区提出自己的问题，例如重新计算增长率或比较两个概念。

![CAGR 的解释与原文并排显示](docs/images/explain.png)

![针对原文主张查看来源、引用片段和核对状态](docs/images/sources.png)

这张图展示一条已保存的历史记录：引用片段已经核对，但旧记录不足以确认当时是否执行过搜索。界面保留这一区别，不把片段核对等同于主张已证实。

![根据原文数字提出具体问题并查看回答](docs/images/question.png)

同一选区的解释、来源和问题分别保留。点击知识贴顶部摘录可回到原文位置。找到链接不等于主张已被证实；未取得或未核对的片段会明确标注，失败、中断和没有找到资料也不会显示成成功。

想问整篇材料时，可选择「向全文提问」。短文使用完整可用文字；长文提供最多 16,000 字符的结构和相关片段，并说明覆盖范围。原生文字不足的 PDF 不会自动用 OCR 代替全文材料。

### 4. 在 PDF 原页上选字或框选图片

PDF 连续滚动，目录优先使用内置书签；没有书签时在本机识别标题。含文字层的 PDF 可直接选字；扫描页、图片或复杂版面可用「框选内容」，把图片和必要说明一起交给所选功能。只有选择解释、来源或提问后，才会进行本机识别并发起模型请求。

![合成 PDF：文件身份、页码、缩放工具与原版图文版式](docs/images/pdf-reading-2026-10-14.png)

![在 PDF 原页框选图片与说明并选择理解方式](docs/images/pdf-selection.png)

### 5. 保存网页文章，必要时译成中文

![真实导入的公开网页：原文、链接和本机保存的静态图片](docs/images/web-images-2026-10-14.png)

选择「+ → 网页链接」，粘贴公开 HTTPS 文章地址。普通网页会提取静态正文及必要图片，完整保存后再打开；导入本身不调用模型。保存后的副本可在原站暂时不可达时继续阅读，重复添加同一链接会打开已有条目，不会自动更新或翻译。

**X 内容：** 在同一输入框粘贴 X/Twitter 的帖子或文章链接，点击「阅读文章」。公开文章、普通帖和长帖通过 FxTwitter 获取；发送公开内容 ID，必要时用链接中的公开账号名定位文章，不发送阅读库、知识贴或登录凭据。来源详情保留渠道及保存范围，服务响应不等于独立核验原站全文。重复来源打开已有副本，不覆盖知识贴。

完整正文、代码、支持的表格和成功取得的图片保存在本机。X图片暂时未取得也可阅读正文：缺图位置明确未保存并提供安全原图链接，保存状态显示正文与缺图数量；不会自动补图。文章内嵌帖子保留原帖链接，并明确其正文未保存，不会自动额外抓取。X 视频保留原站播放链接；若来源提供预览图，会尝试保存到本机，视频文件不下载；只保存当前帖子和接口已附的有界引用，不自动抓取整条讨论串。内部文章 ID 若无法安全关联，需使用原分享帖链接；带账号名的文章只查一次有限候选，不扫描整个账号。旧捕获副本和来源范围保持。

![英文网页的中文译文与原文旁知识贴，工具栏可切换阅读面](docs/images/web-reading.png)

所有导入网页/X的非中文正文都可主动译中。没有译文时，语言图标开启授权；已有译文时只切换原文/中文。部分结果常驻显示「已翻译 X / Y 个文本块」和「继续翻译」，只生成缺失部分；全块已收到但保存失败时可「重试保存译文」，不再次生成。运行中可直接「停止翻译」。

悬停或键盘聚焦计数可阅读标题、段落、列表项、表格单元格及长段拆分说明，无需点击。计数只随已校验结果增加；从本次启动开始累计等待秒数，贯穿准备、请求和保存，跨批不归零，不显示虚假百分比。首次使用说明发送范围；译文分批保存，停止或失败保留已确认部分。切换已保存阅读面不会请求模型；原文与知识贴对应关系保持。

新翻译及主动续译的缺失部分使用专用 `gpt-6-luna / medium`，不改变解释、查证的模型偏好；不可用时明确失败，不自动换模型。提示要求按语境使用自然中文，同时完整保留原意、限定和格式。已有译文保留，旧模型部分成果不会重复生成；内部记录实际参与生成的模型集合。结构校验不能保证所有语义无误，重要术语仍可对照原文。

若模型漏掉原格式标记，仅这些失败文本块会在同一批时间预算内补译一次，其余有效块不重复请求；补译仍失败则保留先前成果。成功时显示本轮修复块数。网络、超时及其它可检测质量错误不会触发这次格式补译，错误提示不展示内部诊断JSON。

代码块、行内代码、链接目标、图片、图片 alt 和图中文字保持原样，不发送翻译模型；普通图注仍可能作为正文翻译。Markdown和PDF不提供全文翻译。已有自动偏好仍仅适用于之后确认新建的英文网页，不因支持其他语言而扩大授权；其他语言需主动开启。

普通链接导入面向可直接读取的静态文章，不保证兼容任意网站。X适配受 FxTwitter 可用性和返回结构影响；私密、删除、身份不符、无法可靠表示的正文及不安全资源会明确报错；图片暂时无法取得则保留明确缺图状态，不替你登录或用AI补写原文。不可用引用会保留明确状态与原站链接，不声称其正文已保存。普通静态导入仍拒绝登录、访问挑战、仅由JavaScript生成的正文和不支持媒体。静态文章有可靠公开正文及明确可见付费边界时，可保存付费墙前的公开部分，界面持续提示“仅保存公开部分”；无需逐篇许可。登录要求、公开正文不足或边界不明仍失败，不读取隐藏或付费墙后的内容；必要媒体失败仍阻止一键加入。

### 6. 等待真实保存，再关闭或切换

界面显示真实保存状态：写入中为「保存中」，成功后显示「已保存」，部分位置使用更完整的「已保存到本机」。翻译进度和错误与保存状态分开显示，翻译完成不会掩盖仍在保存或保存失败。保存失败可重试；冲突时双方记录都会保留，供你核对后选择。

按钮的默认、悬停、按下、禁用、选中和键盘焦点状态采用统一规则，同时保留主操作、次操作和危险操作的层级。设计与开发依据见 [UI 规范](docs/ui-guidelines.md)；[按钮状态展示页](docs/ui/button-states.html) 需下载仓库后用浏览器打开，GitHub 页面不会直接运行这份 HTML。

## AI、来源与主动权

- 打开材料、切换阅读面、展开输入框或回看已有知识贴不会调用模型；事先开启的自动译中偏好只会在确认加入新的英文网页后触发。
- Enter 发送问题，Shift+Enter 换行；停止、超时或失败会保留已经收到的内容并提供重试。
- 选区请求只发送当前选区、有限邻近上下文、标题和必要的知识贴历史；只有明确选择全文提问或网页翻译时，才准备对应的更大范围材料。
- 来源核对只读取有限数量的公开网页，不携带浏览器登录凭据。系统不保证找到最初出处，也不会自动追加查找轮次。
- 解释与查证等知识贴默认使用 **GPT-6.1 SOL / medium**；网页翻译独立固定使用 **GPT-6 Luna / medium**。AI 设置读取本机 Codex 返回的可用模型；所选配置不可用时会提示，不会静默换成其他模型。
- 预计阅读时间在本机计算，不消耗模型额度。**本地保存不等于模型离线运行。**

## 快速开始

| 项目 | 当前基线 |
| --- | --- |
| Node.js | **24.14.1，Node 24 系列**（见 `.nvmrc`） |
| npm | **11.x** |
| 系统 | macOS Apple Silicon 已实测；Windows/Linux 实验性 |
| AI | 本机已安装并登录的 Codex；模型列表由本机 Codex 返回 |
| 网络 | 安装依赖、AI 回答、网页导入和来源查找需要联网 |

克隆或下载代码，进入项目目录。若使用 nvm，可先运行 `nvm install` 和 `nvm use`。

```bash
npm ci
npm run build
npm start
```

浏览器默认打开 <http://127.0.0.1:8787/>。保持终端运行，按 Ctrl+C 停止；之后可直接运行 `npm start`，更新代码后重新安装并构建。`npm ci` 需包含开发依赖，因为本地启动也使用 `tsx`。

1. 打开顶部 **AI 设置**，检查 Codex 连接；未登录时可从界面前往官方授权页，或在终端运行 `codex login`。
2. 添加 Markdown / PDF 本地文件或网页链接，也可以先体验内置示例。
3. 选中原文或 PDF 区域，选择解释、来源或提问。
4. 等待界面确认已保存后关闭；下次启动可继续阅读。

got it 不读取、复制或保存 Codex token。macOS 优先使用系统或用户 Applications 中的 Codex.app / ChatGPT.app，其次使用 PATH 中的 `codex`；也可通过 `CODEX_CLI_PATH` 指定。

开发模式：

```bash
npm run dev
```

前端为 `127.0.0.1:5173`，API 为 `127.0.0.1:8787`。设置 `BROWSER=none` 可禁止自动打开页面；PowerShell 使用 `$env:BROWSER="none"`。应用不会自动读取 `.env`，配置说明见 `.env.example`。

## 保存与隐私

- Markdown 和网页正文副本、网页静态媒体、PDF 原文件副本、识别资源、裁图、知识贴、译文、回答和学习状态保存在本机磁盘，不改写原文件。浏览器只保存偏好和必要的应急恢复数据。
- 默认数据目录：macOS `~/Library/Application Support/Got-it`；Windows `%LOCALAPPDATA%/Got-it`；Linux `$XDG_DATA_HOME/got-it` 或 `~/.local/share/got-it`。可用 `GOT_IT_DATA_DIR` 指定；同一数据目录只运行一个服务。
- PDF OCR 在本机进行，安装时准备简体中文和英文模型。图片解释会把你确认的裁图发送给模型。
- 本机保存不等于异地备份。重要成果请在停止服务后备份整个应用数据目录；不要通过清除浏览器数据处理保存问题。
- 本地 API 默认仅监听回环地址，**不要直接暴露到公网**。GitHub Pages 不能代替本地 API。

## 当前限制

- 当前仅支持 Codex，需要自己的可用账号、网络和模型额度；同一时间只展开一份材料。不支持 Word、原文编辑、账号、云同步或多人协作。
- PDF 上限为 50 MiB、200 页且不能加密。OCR 首轮覆盖简体中文和英文，单次识别限 60 秒；复杂排版、数字和小字可能识别错误，应回到原页核对。裁图最长边 4096 像素、上限 8 MiB。
- 自动生成的 PDF 目录可能遗漏或误读标题，当前不能手工编辑。全文提问也不能保证覆盖长文每一处内容。
- 网页只保存可可靠提取的静态正文和受支持媒体，不运行原站交互。动态 WebP、APNG 和视频不支持；复杂结构可能被拒绝。图片资源有限额，超限时会明确失败，不会悄悄截断。
- Markdown 本地相对路径图片尚未补齐；跨段选区不支持。原文变化较大时，已有知识贴锚点可能需要重新定位。
- 当前没有备份下载按钮；PDF 和网页需要备份完整应用数据目录。旧 Focus Stickies 工作区、`.focus` 和完整 JSON 仍可导入。
- 「已有回答」不代表已经理解或证实。取消、断线和超时不会用演示回答冒充成功。

## 开发与发布检查

```bash
npm test
npm run build
npm run test:release
npm audit --audit-level=high
```

`build` 包含 TypeScript 检查；`test:release` 使用临时数据目录验证构建页面、静态资源、本地服务和 API 边界，不调用模型。更多信息见 [发布检查清单](docs/release-checklist.md)、[发布验证结果](docs/release-results.md) 和 [安全说明](SECURITY.md)。

维护者使用 `npm run release:prepare` 生成公开白名单快照，再同步到独立的公开仓库。不要直接推送内部开发仓库；发布前需单独检查截图和文本是否适合公开。
